# Code of Conduct

## Our standards

Project spaces must remain useful and safe for contributors and users. Examples of acceptable behavior include:

- Show empathy and respect.
- Give specific, constructive technical feedback.
- Accept responsibility and correct mistakes.
- Focus on what benefits the project and its users.
- Respect different experiences, viewpoints, and identities.

Unacceptable behavior includes:

- Sexualized language, imagery, or attention.
- Insults, harassment, threats, or personal attacks.
- Trolling or sustained disruption.
- Publishing another person's private information without permission.
- Pressuring anyone to disclose personal information.
- Behavior that would reasonably be considered inappropriate in a professional setting.

Disagreement about code or project direction is not misconduct. Address the work, not the person.

## Scope

This code applies in repository issues, pull requests, reviews, discussions, and other project spaces. It also applies when someone officially represents the project in public.

## Reporting

Report conduct concerns to project maintainers. For a private report, use the [private reporting form](https://github.com/Jeecabs/moron-guard/security/advisories/new). State that the report concerns behavior, not a vulnerability. If that form is unavailable, open an issue without sensitive details. Ask for a private contact channel.

Include links, screenshots, or other context when safe to do so. Do not investigate, confront participants, or publish private details yourself.

Maintainers will review reports as privately and promptly as circumstances permit. They may remove, edit, or reject contributions and may temporarily or permanently restrict participation. Anyone directly involved in a report must not make the final enforcement decision.

## Enforcement

Responses should match the conduct and its effect. Possible responses include:

1. **Correction:** A private explanation and request to change behavior.
2. **Warning:** A formal warning, with conditions for continued participation.
3. **Temporary restriction:** A time-limited ban from project interaction.
4. **Permanent restriction:** Permanent removal from project spaces.

Do not retaliate against someone who makes or helps with a good-faith report. Knowingly false or malicious reports may violate this code.
